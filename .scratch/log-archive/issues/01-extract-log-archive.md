# 01 — 提取日志归档 module，把历史读取测试面下沉

**What to build:** 读取一页历史日志的逻辑从插件启动函数中提取为独立的日志归档 module，通过它自己的「读取一页」interface 调用与测试；事件监听器降为把请求转交日志归档的薄 adapter。用户可见行为不变：分页结果、顺序、游标、是否还有更早记录都与现在一致。维护者可用真实临时目录直接驱动日志归档，不必再构造假 Koishi 运行时。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 新增日志归档 module，集中已落盘历史日志的分页读取：查询规范化、游标判定、筛选编译、分页早停、排序、下一游标，以及读取前的写入同步与读取容错。对外只暴露「读取一页」一个入口，倒序流式读取生成器作为内部 seam 不进 interface。
- [ ] 日志归档采用与现有服务端 module 一致的类形态，构造接收依赖：日志目录、共享文件清单、读取前的同步动作、非忽略错误的上报回调。核心不依赖 Koishi console 运行时类型。
- [ ] 文件清单由插件启动函数持有并注入，写入路径与读取路径共享同一份；日志归档只读取其倒序清单，不独占或复制清单状态。
- [ ] 「读取前先同步写入」的时序封在日志归档内，由注入的同步动作执行，调用方无法漏掉；装配层只提供同步的具体实现。
- [ ] 缺失文件（`ENOENT`）的静默判定属于日志归档；非忽略错误经注入的上报回调交给装配层，容错行为可在测试中直接断言，不依赖全局日志器。
- [ ] 日志归档组合既有文件清单、倒序读取与筛选编译 module，不拆解也不复制这些下层算法；只服务读取一页的纯函数（查询/筛选/搜索路径规范化、日期校验、游标比较与编码、记录比较与排序）随 module 迁移。
- [ ] 一页读取的请求与结果类型随日志归档导出；Koishi console 的事件与 service 类型注册留在插件启动文件并引用这些类型；日志归档不 import Koishi console。
- [ ] 事件监听器降为薄 adapter，只把请求转交日志归档并返回其结果；过期清理、文件滚动、日志写入、近期日志缓冲与最近日志读取仍属生命周期层，不迁入日志归档。
- [ ] 保持 `CONSTRAINTS.md` 日志文件规模约束：单日十万级文件不展开大数组、凑够一页即停止读取更早文件、清理/读取遇缺失文件不产生任何上报；这些约束在提取后由日志归档保证并有测试覆盖。
- [ ] 先完成提取并让现有装配层历史读取测试原样跑绿当搬运护栏，再把这些测试改写为直接驱动日志归档 interface，保留其分页、大规模、跨文件、早停、筛选与文件竞态断言。
- [ ] 通过日志归档 interface（真实临时目录 + 注入共享文件清单/同步/上报）补齐并断言：分页与游标、十万级文件不展开数组、跨文件顺序、凑页早停、等级与关键词组合、无条件不读盘、非法日期返回空、读取前完成同步、单文件失败仍组页、文件被删无上报。测试不启动 Koishi 插件、不构造假 console/context/logger，不断言私有状态或源码文本。
- [ ] 保留一条插件装配层接线测试，证明事件监听器把请求转交日志归档并返回其结果；过期清理的启动/跨日测试与下层 module 既有测试保留不删。
- [ ] 运行项目测试、可用的类型检查与项目构建并记录结果；说明类型检查的实际命令与范围，不把前端打包等同于服务端类型检查，不主动运行浏览器测试。

## Execution constraints

本工单是行为不变的提取，不改变读取结果、游标格式、文件格式、页大小或 Koishi 事件契约。不推进候选3（身份/游标语义收口），不改写筛选算法或客户端展示。不使用 subagent 做实现，代码实现由主 Agent 完成；不创建分支、不自行提交。
