# 02 — 接入日期查询并统一模式切换

**What to build:** 用户按日期查看、翻页和重试时，同样通过日志会话获得一致行为；在日期与实时模式之间快速切换，不会串入旧日期、旧筛选或迟到请求的数据。分页正确性不再依赖销毁并重建日志展示子树。

**Blocked by:** 01 — 接通非日期日志会话与可靠分页

Status: ready-for-agent

## Acceptance criteria

- [ ] 日期查询接入第一张工单建立的同一个日志会话 module，实际页面使用统一的查询、加载、分页和失败处理路径，不另建第二套会话或分页状态机。
- [ ] 日期查询数据独立于实时流和共享历史缓存；实时日志到达不改变日期结果，也不将日期页写入非日期共享历史缓存。
- [ ] 选择日期加载对应第一页，后续加载沿用该查询的服务端游标与 hasMore；重复加载、末尾状态及失败重试遵循已建立的统一规则。
- [ ] 切换日期先清空上一日期的展示与分页进度；第一页失败保持空结果、提示失败并允许重试第一页，不回退展示上一日期记录。
- [ ] 日期查询同时携带当前插件、等级、关键词及搜索路径条件，保持既有筛选匹配语义；切换这些条件重新建立对应日期查询的分页进度。
- [ ] 从日期返回非日期模式时恢复符合当前条件的实时数据和共享历史缓存，不混入日期结果，不沿用日期游标；保留非日期查询既有的第一页加载策略。
- [ ] 进入日期模式不会无故丢弃共享历史缓存；离开日期后仍可按当前非日期条件复用。
- [ ] 日期之间、日期到非日期、非日期到日期的切换均使旧请求失效。旧请求成功、失败或结束不能污染新模式的数据、分页状态、错误或加载标记。
- [ ] 日期前插仍通过既有 LogViewport around 行为保持阅读位置。补充模式切换与异步前插交叠的协作测试，证明旧操作不会对新查询施加过期数据或位置恢复；不改视口核心和 interface。
- [ ] 删除迁移完成后的父子重复请求编排、独立游标与 hasMore 等分页状态；日志展示只消费会话结果并传递意图，不再拆传多个查询字段后自行重新拼装请求。
- [ ] 分页重置由日志会话完成，不依赖 Vue 子树重挂；移除或收窄相关重挂接线时保持原有查询切换的视口重置语义，不把数据迁移变成滚动行为变更。
- [ ] 历史卸载计时暂保留原有可用接线，通过统一会话意图清空两种模式的历史、分页状态并使请求失效；日期卸载仍清除日期、保留其他筛选，避免迁移期间出现双份状态或自动回填。计时所有权的完整迁移留给下一张工单。
- [ ] 通过日志会话公开 interface 补充日期隔离、日期失败重试、跨模式共享缓存保留、双向模式切换和响应乱序的行为测试；少量 adapter 协作测试验证真实页面接线，不读取私有状态。
- [ ] 保留已有非日期会话、服务端分页和视口安全网；只删除已被行为测试替代的相关源码字符串断言，不批量清理无关展示约束测试。
- [ ] 运行项目测试、可用类型检查和项目构建并记录结果；不把前端打包等同于完整 Vue 类型检查，不主动运行浏览器测试。

## Execution constraints

依赖第一张工单已经接通的日志会话及分页行为。完成后两种查询模式都由同一 module 管理，可独立验证模式切换；自动卸载仍可用，但完整时间调度迁移由下一张工单负责。不重写服务端协议、筛选算法、UI 外观或 LogViewport。不使用 subagent，不创建分支、不自行提交。
