# 03 — 收口历史卸载、保活与会话销毁

**What to build:** 两种浏览模式由日志会话统一管理历史生命周期。用户浏览时延后卸载，启用自动卸载且达到原有空闲时长后释放历史；迟到请求、日期同步和已经销毁的会话都不能把数据重新填回，用户仍能手动恢复历史加载。

**Blocked by:** 02 — 接入日期查询并统一模式切换

Status: ready-for-agent

## Acceptance criteria

- [ ] 日志会话接管自动卸载开关、30 分钟时长、计时开启/重置/停止与销毁规则；Vue adapter 仅传递配置、浏览活动和生命周期意图，不继续持有独立的历史生命周期策略。
- [ ] 时间调度以可控依赖注入，测试可推进时间而不等待真实 30 分钟、不隐式替换全局计时器；是否应计时由日志会话决定。
- [ ] 只有符合既有已加载历史条件时才开启卸载计时，历史加载完成后按原有语义更新计时；无历史时不产生无意义的周期卸载。
- [ ] 保留现有浏览保活事件语义，相关用户操作延后卸载；实时日志推送本身不计作用户活动，不能无限延长历史保留时间。
- [ ] 关闭自动卸载取消计时；重新启用后仅在符合条件时恢复调度。反复更新配置或浏览活动不会积累多个有效卸载回调。
- [ ] 到期统一清空共享历史缓存、日期结果、游标、hasMore 所代表的分页进度及旧加载/失败状态，使在途请求失效；保留实时来源，不要求重新挂载展示才能完成清理。
- [ ] 卸载发生于日期模式时清除日期并返回实时模式，保留插件、等级与关键词筛选；非日期模式卸载同样保留当前筛选。
- [ ] 卸载以及日期清除引发的响应式接线均不立即请求历史；即使仍有有效非日期筛选，也不能刚卸载就自动回填。
- [ ] 卸载后“查看更多消息”可重新启动正确的历史加载；不能沿用已清除的游标，也不能把卸载前的末尾状态误当成永久不可加载。
- [ ] 卸载后的新查询变更仍按正常查询策略执行，能够区别于卸载本身引发的日期同步，不因抑制回填而屏蔽真正的用户意图。
- [ ] 覆盖第一页或后续页在途时卸载：迟到成功、失败和结束处理均不能重新写入历史、恢复旧游标、修改新请求状态或显示过期错误。
- [ ] 销毁日志会话清理计时并使全部请求失效；销毁后的响应和计时回调不再发布状态。复用现有页面激活、失活及卸载语义，不无故把短暂离开页面当成销毁。
- [ ] 通过公开 interface 与可控时钟验证两种模式的计时、保活、开关切换、卸载、日期同步不回填、手动恢复和销毁；测试断言外部结果，不断言私有计时器或实现函数。
- [ ] 补充卸载与异步前插交叠的 LogViewport 协作测试，保证旧操作不能污染新会话或造成过期位置恢复；保留锚点、虚拟滚动和既有视口行为。
- [ ] 删除剩余旧历史计时和生命周期编排及不再使用的迁移接线，仅替换已有行为覆盖的客户端源码字符串断言。保留无关展示约束及全部现有服务端、视口安全网。
- [ ] 核对整份日志会话规格的行为均有对应实现和验证，尤其是查询隔离、失败重试、共享缓存与日期隔离，不把最终验收变成另一张补测试工单。
- [ ] 运行完整项目测试、可用类型检查和项目构建并记录通过情况及失败原因；不把前端打包等同于完整 Vue 类型检查，不主动运行浏览器测试。

## Execution constraints

依赖两种查询模式已经统一进入日志会话，才能完整接管卸载与模式同步。完成后没有仍由展示调用方驾驶的分页或历史生命周期状态。关键异步交点需注释卸载失效与禁止自动回填的原因。不改配置传输、服务端文件策略、筛选算法、UI 外观或 LogViewport 核心。不使用 subagent，不创建分支、不自行提交。
