# refactor：集中日志会话的查询、分页与历史生命周期

Status: ready-for-agent

## Problem Statement

用户查看日志时，一次连续浏览会同时涉及实时更新、筛选、加载更早记录、失败重试与历史自动卸载，但这些行为目前没有统一的日志会话所有者。第一页和后续页分别持有状态，第一页已经到头时仍可能显示加载入口；筛选或卸载与请求交叠时，也缺少覆盖全部请求的统一过期响应裁决。

这种分散使用户难以获得一致的分页结果，也使维护者必须同时理解父子展示 module 的查询传递、游标更新、日志合并和重建顺序。服务端分页与视口各自已有行为测试，但客户端会话主要依赖源码字符串断言：无害的重命名会破坏测试，真正的异步状态错误却可能不被发现。

## Solution

建立日志会话 module，集中一次连续日志浏览中的查询、展示数据、分页进度和历史生命周期。用户仍使用原有筛选和“查看更多消息”入口，但第一次查询与后续加载遵循一致的加载、结束和重试规则；切换查询或卸载历史后，迟到结果不能污染当前浏览。

保留非日期查询的共享历史缓存，切换筛选只重置当前查询的分页进度，不丢弃全部已加载历史。日期查询保持独立。日志会话决定哪些记录进入清单，LogViewport 继续负责清单变化时的位置稳定，两者不互相接管职责。

## User Stories

1. 作为查看日志的用户，我希望未设置筛选时仍优先显示实时日志，以便不必等待磁盘历史查询。
2. 作为查看日志的用户，我希望更早的日志仍由点击“查看更多消息”触发，以便自行控制历史加载量。
3. 作为查看日志的用户，我希望插件、等级和关键词筛选继续影响当前展示，以便找到符合条件的记录。
4. 作为查看日志的用户，我希望关键词继续覆盖日志正文、插件名及自定义标签，以便保持现有搜索能力。
5. 作为查看日志的用户，我希望输入关键词仍按现有防抖策略发起查询，以便避免逐字请求历史。
6. 作为查看日志的用户，我希望筛选或日期查询的第一页与后续页使用同一份查询条件，以便翻页结果不会偏离当前选择。
7. 作为查看日志的用户，我希望第一页加载期间不会重复启动同一查询的后续页，以便避免重复请求和游标竞争。
8. 作为查看日志的用户，我希望重复点击加载入口不会并发请求同一页，以便分页顺序保持可靠。
9. 作为查看日志的用户，我希望第一页已经没有更多记录时不再出现可继续加载的入口，以便准确知道查询是否结束。
10. 作为查看日志的用户，我希望后续页沿用当前查询已返回的游标，以便不重复读取已经翻过的页。
11. 作为查看日志的用户，我希望没有历史分页游标时仍能从当前实时浏览继续加载更早记录，以便保留现有无筛选浏览方式。
12. 作为查看日志的用户，我希望共享缓存里的旧记录不会让新查询跳过尚未查询的历史区间，以便分页结果不因缓存内容而遗漏。
13. 作为查看日志的用户，我希望相同日志同时出现在实时流和历史页时只显示一次，以便不会误认为产生了重复日志。
14. 作为查看日志的用户，我希望合并后的日志维持既有时间与身份顺序，以便连续阅读。
15. 作为查看日志的用户，我希望切换筛选后已加载的非日期历史仍可复用，以便不必反复加载相同数据。
16. 作为查看日志的用户，我希望共享历史缓存始终按当前条件过滤，以便不会看到只符合旧筛选的记录。
17. 作为查看日志的用户，我希望清除筛选后仍能看到之前加载的非日期历史，以便保持既有浏览体验。
18. 作为查看日志的用户，我希望切换查询时重新建立分页进度，以便旧查询的游标和结束状态不会影响新查询。
19. 作为查看日志的用户，我希望快速连续切换查询时只接受当前查询的响应，以便迟到请求不会覆盖新结果。
20. 作为查看日志的用户，我希望过期请求失败或结束时也不改变当前查询的加载状态，以便当前操作不会被旧请求干扰。
21. 作为查看日志的用户，我希望选择日期后只显示该日期查询的记录，以便实时流和其他历史不会混入结果。
22. 作为查看日志的用户，我希望更换日期时不残留上一日期的展示，以便不会将旧记录误认成新日期的结果。
23. 作为查看日志的用户，我希望第一页查询失败时仍保留当前非日期条件下可用的实时和缓存记录，以便失败不会清空已有信息。
24. 作为查看日志的用户，我希望第一页失败后能重试第一页，以便不会错误地从旧查询游标继续加载。
25. 作为查看日志的用户，我希望日期查询第一页失败时保持空结果并允许重试，以便不展示上一日期的数据。
26. 作为查看日志的用户，我希望后续页失败时保留已有记录和游标，以便重试能够继续同一页。
27. 作为查看日志的用户，我希望请求失败有错误提示，但不被当作没有更多记录，以便区分失败和正常结束。
28. 作为查看日志的用户，我希望加载更早记录后仍停留在原来阅读的位置，以便前插不会打断阅读。
29. 作为查看日志的用户，我希望加载期间切换查询不会让旧请求触发错误的数据写入或位置恢复，以便新查询不受旧操作影响。
30. 作为查看日志的用户，我希望当前浏览操作仍能延后自动卸载，以便正在阅读的历史不会因原有计时到期而被清空。
31. 作为查看日志的用户，我希望启用自动卸载后，沿用现有 30 分钟无相关浏览操作的卸载规则，以便释放不再查看的历史数据。
32. 作为查看日志的用户，我希望关闭自动卸载后不再按该规则清空历史，以便保留手动加载的记录。
33. 作为查看日志的用户，我希望卸载同时清空历史数据、游标与分页状态，并使在途请求失效，以便迟到响应不能把历史重新填回。
34. 作为查看日志的用户，我希望日期浏览发生自动卸载后清除日期并返回实时模式，但保留插件、等级和关键词选择，以便维持既有筛选语义。
35. 作为查看日志的用户，我希望卸载后不立即自动查询历史，以便释放的数据不会马上再次占用内存。
36. 作为查看日志的用户，我希望卸载后仍能点击“查看更多消息”重新加载，以便按需恢复历史浏览。
37. 作为插件维护者，我希望会话重置不依赖销毁展示子树才能清空分页状态，以便数据正确性不再依赖 Vue 重挂协议。
38. 作为插件维护者，我希望调用者只通过日志会话 interface 表达意图并读取结果，以便不必分别维护请求、游标和缓存的执行顺序。
39. 作为插件维护者，我希望日志会话与 Vue、DOM 和 Console transport 的具体实现隔开，以便无浏览器也能驱动完整会话行为。
40. 作为插件维护者，我希望测试能够精确控制请求返回顺序和时间推进，以便稳定复现竞态、重试与卸载交叠。
41. 作为插件维护者，我希望测试断言可观察结果而非源码文字或私有变量，以便内部重构不会损坏行为安全网。
42. 作为插件维护者，我希望保留已有服务端分页和 LogViewport 行为测试，以便本次会话重构不会降低既有保障。
43. 作为后续接手的维护者，我希望会话规则集中在一个 module，并在关键异步交点有不变量注释，以便无需跨多个展示 module 猜测时序。

## Implementation Decisions

### 日志会话的所有权

- 新增日志会话 module，核心采用纯 TypeScript，不依赖 Vue、DOM 或 Koishi Console 运行时。
- module 集中持有当前查询、历史数据、分页进度、加载与失败状态、响应有效性及历史卸载规则。第一页与后续页不能分别由两个调用者拥有。
- 共享历史缓存与当前查询的分页进度是不同概念：缓存可跨非日期筛选保留，游标、结束状态和请求有效性必须属于当前查询。
- 日期查询的数据独立保存，不与实时流或共享历史缓存混合；切换日期不保留上一日期的展示结果。
- 展示记录继续沿用已有身份、合并去重、排序与筛选规则，不顺带重构跨端身份语义。
- 实时数据仍使用现有推送来源；不复制或接管全局实时日志存储。

### interface 与 adapter

- 日志会话对外 interface 应覆盖查询更新、实时数据更新、加载更早记录、浏览保活、自动卸载配置变化和销毁等意图，并提供一致的只读会话结果；具体方法名称和类型形状由实现阶段确定。
- 调用者不得通过独立修改游标、hasMore 或私有加载标记来驾驶会话。
- Vue adapter 仅承担响应式绑定、展示意图转交及生命周期接线，不重新持有另一份分页状态。
- Console adapter 复用既有请求 seam，只负责传输；不新增通用网络框架或改变服务端请求与返回约定。
- 时间调度作为可控依赖注入；何时开启、重置或停止卸载计时由日志会话决定，而非分散在多个展示调用处。
- 插件名称与标签解析、筛选控件展开和搜索输入防抖继续属于现有展示职责；会话接收已经形成的查询条件。

### 查询与分页

- 保留无筛选进入时只显示实时数据、手动加载更早日志的行为；日期或有效筛选变化按既有策略查询第一页。
- 第一页与后续页共享同一查询的加载裁决，阻止同一查询的重入与重复翻页；旧查询在途请求不能阻塞新查询开始。
- 查询切换重新建立分页进度并使旧请求失效，非日期共享历史缓存不随之整体清空。
- 第一页响应的游标与 hasMore 必须进入当前会话状态，后续页以服务器返回游标继续。
- 未建立分页游标的无筛选浏览沿用既有加载起点语义；起点选择集中在会话，不由日志展示临时拼接。共享缓存不能让新的筛选查询跳过第一页或未扫描区间。
- 响应有效性同时覆盖成功、失败与结束处理。旧请求不能写入当前数据、推进游标、改变加载标记或发出误导当前查询的错误提示。
- 相同查询条件不能仅因派生数组引用变化而重复加载；继续按条件内容判断变化。

### 失败与重试

- 非日期第一页失败时，保留符合当前条件的实时记录及共享历史缓存；允许重试第一页，不沿用上一查询游标。
- 日期第一页失败时保留空结果并允许重试，不回退展示上一日期。
- 后续页失败保留既有记录与分页游标，重试仍请求同一逻辑页。
- 当前请求失败必须提供错误提示，但失败不等于正常到达历史末尾。
- 无需新增错误展示面板或改变现有 UI 外观；错误通知由展示 adapter 承接，会话核心不直接调用 UI 提示。

### 历史生命周期

- 维持自动卸载开关与 30 分钟时长，以及现有浏览保活事件语义；不把每次实时日志推送视为用户浏览活动。
- 沿用只在存在已加载历史状态时计时的规则；关闭自动卸载或销毁会话时清理相应调度。
- 卸载统一清空共享历史缓存、日期查询数据和分页状态，同时使所有旧请求失效。
- 卸载发生于日期查询时清除日期，保留插件、等级与关键词条件并返回实时模式。
- 卸载及其引起的日期同步不得自动触发历史回填；只有后续明确加载意图或新的查询变更才能再次加载。
- 重置正确性由日志会话保证，不以销毁并重建展示子树作为分页状态清理手段。现有视口重置行为不得因此无意改变。
- 会话销毁后，迟到响应与计时回调不得继续发布状态。

### 与 LogViewport 协作

- LogViewport 仍独占视口位置、虚拟窗口、锚点与恢复编排；日志会话不包含这些 implementation。
- 会造成历史前插的变更继续经过既有 around 行为，保证先保存位置、再改变数据、最后按现有协议恢复。
- 数据写入前必须确认请求仍属于当前会话；查询切换或卸载与前插交叠时，旧操作不能污染新数据，也不能对新查询施加过期的位置恢复。
- 不新增 DOM seam，不改变现有 LogViewport interface 或核心。调用处接线需通过协作测试证明遵守既有协议。

## Testing Decisions

### 主要测试 seam

主要测试面是日志会话 module 的公开 interface，生产 Vue adapter 与测试使用同一入口。测试断言展示记录、加载/结束/可重试状态、请求参数与次数、错误通知及生命周期结果，不访问私有变量、不读取源码字符串、不依赖内部函数调用形状。

Console 请求 seam 在生产中使用现有 transport adapter，在测试中使用可控制成功、失败和响应顺序的内存 adapter。卸载通过可推进的时钟验证，不等待真实 30 分钟，不替换全局计时器来隐式耦合测试。

### 行为覆盖

1. 无筛选初始化不自动读历史，手动加载使用正确起点。
2. 有效筛选与日期变化加载第一页；等价查询不因数组引用变化而重复加载。
3. 第一页加载中重复触发加载不会并发启动同一查询的下一页。
4. 第一页返回 hasMore 为 false 后不可继续分页；空结果正确结束。
5. 后续页使用当前查询的服务端游标，重复点击不重复请求。
6. 共享缓存包含较早记录时，新筛选仍从正确的第一页建立进度，不跳过缺失区间。
7. 历史、缓存和实时记录合并后去重且有序，展示只包含当前条件允许的记录。
8. 切换非日期筛选保留缓存并重置分页；清除筛选后缓存仍可展示。
9. 日期结果独立，切换日期清空旧日期，实时到达不混入日期结果。
10. 查询 A 与 B 交叠时，无论 A 成功、失败或最后结束，都不能污染 B 的数据、游标、错误或加载状态；覆盖后续页在途时切换查询。
11. 第一页失败保留可用记录，重试仍为第一页；日期第一页失败为空且可重试。
12. 后续页失败保留原页与游标，可重新请求同一页；失败不改变为正常结束。
13. 自动卸载只在符合条件时调度，浏览活动延后卸载，实时推送不无限保活。
14. 关闭自动卸载取消计时；按现有语义重新开启后恢复调度。
15. 到期卸载清空历史和分页，保留实时数据及非日期筛选，并使在途请求无效。
16. 日期卸载返回实时模式且不因日期同步立即请求历史；手动加载后可恢复浏览。
17. 销毁后请求返回和计时回调均不产生新状态。

### 协作与既有安全网

- 使用已有 LogViewport interface 补充少量会话与视口协作测试，验证前插位置保护，以及查询切换、卸载与异步前插交叠时的隔离。
- 优先复用既有视口行为测试中的可控宿主与调度方式，不引入新的 DOM seam、jsdom 或浏览器测试框架。
- 保留服务端分页的筛选、游标、跨文件顺序、大规模读取及早停测试，保留现有 LogViewport 行为测试。
- 仅替换本次日志会话行为测试已经覆盖的客户端源码字符串断言；不批量删除无关展示约束测试。
- 先例是项目现有裸 Node 测试：视口测试通过公开 interface 与可控依赖驱动异步编排，日志合并测试断言记录结果，服务端分页测试断言真实页结果。
- 实现完成后运行项目测试、可用的类型检查与项目构建。当前没有独立名为 typecheck 的脚本，应使用实际已有命令并准确说明检查范围；不得把客户端打包等同于完整 Vue 类型检查。
- 未明确要求时不主动运行浏览器测试。如后续要求浏览器验收，需遵守 Chrome/Firefox、最新构建与进程重启、会话和临时产物清理规则。

## Out of Scope

- 服务端历史归档读取 module 的提取，以及文件读取、写入、滚动、清理和近期缓冲算法变更。
- 独立推进跨客户端与服务端的身份/游标共享 module，或改变现有身份格式、排序和分页协议。
- 重写 LogViewport 核心、ViewportHost、虚拟列表、锚点恢复或自绘滚动条。
- 修改筛选匹配算法、插件配置传输、权限、页大小或磁盘格式。
- UI 外观调整、新增筛选功能、自动滚动加载历史、全新错误面板。
- 引入通用状态框架、网络框架、额外 DOM 测试框架或全新的事件总线。
- 修改版本、许可证、发布配置或执行发布。
- 本次规格整理不启动实现，不拆分实现工单，不创建分支、不提交代码，不使用 subagent。
